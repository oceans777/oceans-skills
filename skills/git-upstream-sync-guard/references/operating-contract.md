# 上游同步操作契约

## 不变量

1. 官方提交与本地定制必须可区分。
2. 镜像分支只能快进到上游默认分支。
3. `dev` 是二开集成点。
4. `release` 只接受已验证的 `dev` 结果。
5. 自动化不能用强制重置、强推或清理命令消灭证据。

## 初始化验收

- `git remote -v` 能看到 `origin` 与 `upstream`，或明确记录当前只存在官方远端、尚未建立用户 `origin`。
- `upstream/HEAD` 可解析。
- 镜像分支与 `upstream/<默认分支>` 处于相同提交或可快进关系。
- `dev` 不承载在镜像分支上。
- `release` 若存在，其来源和用途明确。

## 同步验收

- 同步前工作区干净。
- 已执行 `git fetch upstream --prune --tags`。
- 镜像分支使用 `git merge --ff-only` 完成更新。
- 合入 `dev` 前存在回退分支。
- 冲突若发生，人工或工具按业务意图解决，并重新运行门禁。
- 门禁失败时没有进入 `release`。

## 推荐维护节奏

高频更新仓库不要积压太久再升级。按项目活跃度建立固定同步节奏；重大安全修复出现时立即单独处理，不等常规同步周期。

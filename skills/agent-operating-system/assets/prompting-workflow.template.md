# Prompt 工作流

目标是让任务可理解、可执行、可验证，而不是追求更长的 Prompt。

## 默认写法

先用自然语言说明想得到的结果。任务较大、风险较高，或者结果会受特定信息影响时，再按需补充：

- **结果**：要完成什么，给谁使用。
- **上下文**：哪些文件、数据、截图、复现步骤或当前事实会改变结果。
- **输出**：需要的格式、长度、语言或详细程度。
- **边界**：最重要的一到三条不能违反的约束，特别是共享副作用。
- **终检**：完成前必须核对的行为、数据、命令或验收条件。

这些都是可选项。简单任务不应为了套模板而增加无效上下文。

## 代码任务

Bug 报告优先给出可复现的操作、实际结果和期望结果。实现者应先复现、定位根因，再选择与根因相称的修复范围。

```text
修复设置页显示“已保存”但刷新后恢复旧值的问题。

复现：……
期望：……
边界：保持现有 API 契约。
终检：重跑复现步骤和最小相关测试，报告命令与结果。
```

## 工具、来源与共享副作用

- 指定工具或数据源时，说明去哪里找什么，不需枚举每个检索步骤。
- 需要复核当前或重要信息时，要求保留来源。
- 资料冲突或不足时，标记缺失和假设，不把推测写成事实。
- 发送、发布、合入、推送和其他会影响他人的动作，必须在当前任务中获得明确授权。
